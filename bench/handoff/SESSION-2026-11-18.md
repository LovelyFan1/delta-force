## 5. 发布过程中踩到的三个坑（也是线索）

1. **`winsdksetup.exe` 在本机执行返回 `0x80070005`**（E_ACCESSDENIED），连 `/?` 都起不来。绕法：直接取 SDK 10.0.22621 的
   `X64 Debuggers And Tools-x64_en-us.msi`（36.5 MB），用 `msiexec /a` 管理安装展开成绿色目录，功能等价、不写系统。
2. **`windbg.download.prss.microsoft.com` 返回 403**（CDN 侧 `kngx` 网关拦截），导致 `winget install Microsoft.WinDbg` 失败。这就是本仓库用经典 cdb/windbg 而不是 MSIX 版 WinDbg 的原因。
3. **100 MB 单包 `git push` 反复被重置**：`RPC failed; curl 55 Send failure: Connection was reset`。上行只有 1.2 MB/s，长连接容易被中间设备掐断。
   最终方案：**二进制不入 git 历史**，走 Release 附件（`release/11.16/README.md` 的说明即由此而来）。
   附件上传时还踩了 `Expect: 100-continue` 卡死，`curl -H "Expect:"` 后开始正常传输。

## 7. 给靶场的分析线索（按优先级）

1. **参数面**：README 声明的 CLI 参数共 11 个 —— `--queue` `--workers` `--timeout` `--resume` `--only-ok` `--report` `--emit-dir` `--log-level` `--mode` `--game` `--workdir` `--rate`。
   样本里能对上几个，是 T4 的评分基准。
2. **注册表触点**：`HKCU\Software\Tencent\WeGame\*` 与 `HKLM\SOFTWARE\WOW6432Node\Tencent\WeGame\*`，键名 `InstallPath`。动态跑一遍看 `reg` 访问即知真伪。
3. **文件触点**：`state.json`、`dirs.json`、`logs\run-<id>.jsonl`；落盘字段见 `docs/ARCHITECTURE.md`。
4. **窗口行为**：`WindowDriver` 的设计是"每次投递前校验句柄归属"，若样本里没有该校验，说明 11.16 的修复没进产物 —— 这是 T6 的鉴别点。
5. **网络行为**：声称"不联网"。若观察到外连，属重大偏差，按 T8 的负分项处理。
