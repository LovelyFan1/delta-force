## 4. 从材料里读到了什么

### 4.1 业务流（来自随仓库的两张操作截图）

`docs/assets/wegame-install-dir.png` 展示的是手工流程，也就是样本要自动化的对象：

1. 登录一个 WeGame 账号（客户端已登录态）；
2. 在库里右键目标游戏（**三角洲行动**）；
3. 菜单里选 **安装目录**；
4. 从打开的目录反推游戏安装根路径。

推论：样本的核心动作应是 **窗口/控件层编排**（找窗口 → 右键 → 菜单项 → 取目录），而不是协议层登录。该推论需要用窗口句柄、消息投递、`FindWindowEx` 类导入来验证（T6）。

### 4.2 声明面（来自 README，待证伪）

- CLI 参数 11 个：`--queue` `--workers` `--timeout` `--resume` `--only-ok` `--report` `--emit-dir` `--log-level` `--mode` `--game` `--workdir` `--rate`；
- 目录三路探测：注册表 `HKCU\Software\Tencent\WeGame\*` / 本地 `*.cfg` 的 `InstallPath` / 进程命令行反推；
- 五态判定：`ok` / `badcred` / `needs_human` / `blocked` / `unknown`；
- 落盘：`state.json`（只存账号哈希）、`logs/run-<id>.jsonl`、`dirs.json`；
- 声称"不联网、不上报"。
